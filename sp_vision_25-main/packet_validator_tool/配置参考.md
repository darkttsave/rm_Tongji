# 配置文件完整参考手册

本文档提供配置文件的完整说明，包括所有字段、选项和高级用法。

---

## 📋 配置文件结构

### 基本结构（YAML格式）

```yaml
# 协议基本信息
protocol_name: "协议名称"
description: "协议描述（可选）"
frame_header: "0xA5"
byte_order: "little"  # 或 "big"

# 字段定义
fields:
  - name: "字段名"
    size: 1
    type: "uint8"
    description: "字段说明"
    validation:
      type: "验证类型"
      # 其他验证参数...

# 模拟器配置（可选）
simulator:
  enabled: true
  generate_rules:
    "字段名": "生成规则"
```

### 基本结构（JSON格式）

```json
{
  "protocol_name": "协议名称",
  "description": "协议描述（可选）",
  "frame_header": "0xA5",
  "byte_order": "little",
  "fields": [
    {
      "name": "字段名",
      "size": 1,
      "type": "uint8",
      "description": "字段说明",
      "validation": {
        "type": "验证类型"
      }
    }
  ],
  "simulator": {
    "enabled": true,
    "generate_rules": {
      "字段名": "生成规则"
    }
  }
}
```

---

## 🔧 顶层配置项

### protocol_name
- **类型**: 字符串
- **必需**: 是
- **说明**: 协议的名称，将显示在工具界面中
- **示例**: `"RM视觉通信协议"`, `"Arduino传感器协议"`

### description
- **类型**: 字符串
- **必需**: 否
- **说明**: 协议的详细描述
- **示例**: `"用于RoboMaster机器人视觉系统的通信协议"`

### frame_header
- **类型**: 字符串
- **必需**: 否
- **说明**: 数据包的帧头标识（仅用于文档说明）
- **格式**: 十六进制字符串，如 `"0xA5"`, `"0xFF"`
- **注意**: 实际验证通过fields中的fixed_value实现

### byte_order
- **类型**: 字符串
- **必需**: 是
- **可选值**: `"little"` (小端序) 或 `"big"` (大端序)
- **说明**: 多字节数据的字节序
- **默认**: `"little"`
- **注意**: 大多数嵌入式系统使用小端序

---

## 📦 字段定义 (fields)

### 字段基本属性

每个字段包含以下属性：

#### name
- **类型**: 字符串
- **必需**: 是
- **说明**: 字段的名称，在表格中显示
- **示例**: `"帧头SOF"`, `"CRC8"`, `"Yaw角度"`

#### size
- **类型**: 整数
- **必需**: 是
- **说明**: 字段占用的字节数
- **范围**: 1-8（根据type决定）
- **示例**: `1`, `2`, `4`, `8`

#### type
- **类型**: 字符串
- **必需**: 是
- **可选值**: 见下表

| 类型 | size | 取值范围 | 说明 |
|------|------|----------|------|
| `uint8` | 1 | 0 ~ 255 | 无符号8位整数 |
| `uint16` | 2 | 0 ~ 65535 | 无符号16位整数 |
| `uint32` | 4 | 0 ~ 4294967295 | 无符号32位整数 |
| `int8` | 1 | -128 ~ 127 | 有符号8位整数 |
| `int16` | 2 | -32768 ~ 32767 | 有符号16位整数 |
| `int32` | 4 | -2^31 ~ 2^31-1 | 有符号32位整数 |
| `float` | 4 | ±3.4E±38 | 单精度浮点数 |
| `double` | 8 | ±1.7E±308 | 双精度浮点数 |

#### description
- **类型**: 字符串
- **必需**: 否
- **说明**: 字段的功能描述，在表格中显示
- **示例**: `"起始标志(0xA5)"`, `"目标距离(米)"`

#### validation
- **类型**: 对象
- **必需**: 否
- **说明**: 字段的验证规则，详见下一节

## ✅ 验证类型详解

### 1. fixed_value - 固定值验证

验证字段的值是否等于预期的固定值，通常用于帧头、魔数等。

```yaml
validation:
  type: fixed_value
  value: 165  # 期望的值
```

**参数**:
- `value` (必需): 期望的数值
  - 可以是十进制: `165`
  - 可以是十六进制: `0xA5` (仅YAML支持)

**示例**:
```yaml
- name: 帧头SOF
  size: 1
  type: uint8
  validation:
    type: fixed_value
    value: 165  # 0xA5
```

**验证逻辑**:
- 读取字段的实际值
- 与期望值比较
- 不相等时报错: "字段名错误: 期望X, 实际Y"

---

### 2. crc8 - CRC8校验

使用CRC8算法验证数据完整性，通常用于包头校验。

```yaml
validation:
  type: crc8
  range: [0, 4]  # 校验范围
```

**参数**:
- `range` (必需): 校验的字节范围 `[起始索引, 结束索引]`
  - 起始索引: 从0开始计数
  - 结束索引: 包含该位置（不是长度）
  - 特殊值: `-1` 表示到当前字段之前

**CRC8算法**:
- 使用标准CRC8查找表
- 初始值: 0xFF
- 多项式: 0x31

**示例1: 校验包头前4字节**
```yaml
# 数据包结构: [SOF(1)] [长度(2)] [序列号(1)] [CRC8(1)] ...
- name: CRC8
  size: 1
  type: uint8
  validation:
    type: crc8
    range: [0, 4]  # 校验索引0-3（前4个字节）
```

**示例2: 使用-1自动计算范围**
```yaml
# 校验从包头到CRC8字段之前的所有数据
- name: CRC8
  size: 1
  type: uint8
  validation:
    type: crc8
    range: [0, -1]  # 自动到当前字段之前
```

**验证逻辑**:
- 提取range指定的数据
- 计算CRC8值
- 与字段实际值比较
- 不匹配时报错: "CRC8校验失败: 计算值XX, 接收值YY"

---

### 3. crc16 - CRC16校验

使用CRC16算法验证整个数据包的完整性。

```yaml
validation:
  type: crc16
  range: [0, -1]  # 通常校验整包
```

**参数**:
- `range` (必需): 校验的字节范围 `[起始索引, 结束索引]`
  - 通常使用 `[0, -1]` 校验整包
  - `-1` 表示到CRC16字段之前

**CRC16算法**:
- 使用标准CRC16查找表
- 初始值: 0xFFFF
- 多项式: 0x1021

**示例: 整包校验**
```yaml
# 数据包结构: [包头...] [数据...] [CRC16(2)]
- name: CRC16
  size: 2
  type: uint16
  validation:
    type: crc16
    range: [0, -1]  # 校验包头到CRC16之前的所有数据
```

**字节序注意**:
- CRC16是2字节数据
- 按照配置的byte_order解析
- 小端序: 低字节在前
- 大端序: 高字节在前

**验证逻辑**:
- 提取range指定的数据
- 计算CRC16值（16位）
- 与字段实际值比较
- 不匹配时报错: "CRC16校验失败: 计算值XXXX, 接收值YYYY"

---

### 4. checksum - 简单校验和

累加指定范围的所有字节，取低8位作为校验和。

```yaml
validation:
  type: checksum
  range: [0, -1]  # 校验范围
```

**参数**:
- `range` (必需): 校验的字节范围 `[起始索引, 结束索引]`

**算法**:
```python
checksum = sum(所有字节) & 0xFF
```

**示例**:
```yaml
- name: 校验和
  size: 1
  type: uint8
  validation:
    type: checksum
    range: [0, -1]  # 校验整包（到校验和字段之前）
```

**验证逻辑**:
- 累加range内所有字节
- 取低8位（& 0xFF）
- 与字段实际值比较
- 不匹配时报错: "校验和失败: 计算值XX, 接收值YY"

## 🎲 模拟器配置 (simulator)

模拟器用于在无硬件的情况下生成测试数据包。

### 基本配置

```yaml
simulator:
  enabled: true  # 是否启用模拟器
  generate_rules:
    "字段名1": "生成规则1"
    "字段名2": "生成规则2"
```

### enabled
- **类型**: 布尔值
- **必需**: 否
- **默认**: `false`
- **说明**: 是否启用模拟器功能

### generate_rules
- **类型**: 对象/字典
- **必需**: 否
- **说明**: 每个字段的数据生成规则
- **键**: 字段名（必须与fields中的name完全匹配）
- **值**: 生成规则字符串

---

## 📊 生成规则详解

### 1. fixed:值 - 固定值

生成固定的值，适用于帧头、魔数等。

**格式**:
- `"fixed:十进制数"` - 例: `"fixed:100"`
- `"fixed:0x十六进制"` - 例: `"fixed:0xA5"`
- `"fixed:浮点数"` - 例: `"fixed:3.14"`

**示例**:
```yaml
generate_rules:
  "帧头SOF": "fixed:0xA5"      # 始终生成0xA5 (165)
  "魔数": "fixed:305419896"    # 固定的32位整数
  "默认角度": "fixed:0.0"      # 固定的浮点数
```

**解析逻辑**:
- 检测 `0x` 前缀 → 按16进制解析
- 包含小数点 → 按浮点数解析
- 否则 → 按整数解析

---

### 2. counter - 递增计数器

生成从0开始递增的整数序列。

**格式**: `"counter"`

**示例**:
```yaml
generate_rules:
  "序列号": "counter"     # 0, 1, 2, 3, 4, ...
  "包ID": "counter"       # 每个数据包自动+1
```

**特点**:
- 每次生成自动+1
- 适用于序列号、包计数等
- 超出类型范围时自动回滚（模运算）

---

### 3. random:最小-最大 - 随机数

生成指定范围内的随机数。

**格式**:
- 整数: `"random:最小-最大"` - 例: `"random:1-100"`
- 浮点数: `"random:最小值-最大值"` - 例: `"random:0.5-10.0"`

**示例**:
```yaml
generate_rules:
  "温度": "random:200-300"        # 20.0°C ~ 30.0°C (整数)
  "湿度": "random:400-600"        # 40.0% ~ 60.0% (整数)
  "距离": "random:0.5-10.0"       # 0.5m ~ 10.0m (浮点数)
  "角度": "random:-180.0-180.0"   # -180° ~ 180° (浮点数)
```

**解析逻辑**:
- 检测范围字符串中是否有小数点
- 有小数点 → `random.uniform(min, max)` (浮点)
- 无小数点 → `random.randint(min, max)` (整数)

---

### 4. formula:表达式 - 公式计算

使用数学公式动态计算值。

**格式**: `"formula:数学表达式"`

**可用变量**:
- `counter` - 当前计数器值（从0开始）

**可用函数** (来自math模块):
- `sin()`, `cos()`, `tan()` - 三角函数
- `sqrt()`, `pow()` - 幂运算
- `pi`, `e` - 常数

**示例**:
```yaml
generate_rules:
  "线性增长": "formula:counter*0.1"           # 0, 0.1, 0.2, 0.3, ...
  "平方增长": "formula:counter*counter"       # 0, 1, 4, 9, 16, ...
  "正弦波": "formula:50*sin(counter*0.1)+50" # 50附近振荡
  "指数增长": "formula:pow(2, counter%10)"   # 1, 2, 4, 8, 16, ...
```

**安全性**:
- 表达式在受限环境中执行
- 不允许访问系统函数
- 仅允许math模块和counter变量

---

### 默认生成规则

如果字段未在generate_rules中指定，使用以下默认规则：

| 字段类型 | 默认规则 | 说明 |
|----------|----------|------|
| `fixed_value` 验证 | 使用验证值 | 自动使用validation.value |
| `crc8` | 自动计算 | 根据range自动计算CRC8 |
| `crc16` | 自动计算 | 根据range自动计算CRC16 |
| `checksum` | 自动计算 | 根据range自动计算校验和 |
| `uint8` | `counter*2 % 256` | 0, 2, 4, ... |
| `uint16` | `counter*100 % 65536` | 0, 100, 200, ... |
| `uint32` | `counter*1000 % 2^32` | 0, 1000, 2000, ... |
| `float` | `counter*0.1` | 0.0, 0.1, 0.2, ... |
| `double` | `counter*0.01` | 0.00, 0.01, 0.02, ... |

## ❓ 常见问题 (FAQ)

### Q1: YAML和JSON有什么区别？

**A**: 功能完全相同，选择其一即可：
- **YAML优点**: 更易读、支持注释、无需引号
- **JSON优点**: 更严格、工具支持更广泛
- **推荐**: 新项目使用YAML

### Q2: 如何确定CRC的range参数？

**A**: 
- `range: [起始, 结束]` 中的索引是字节位置
- 起始通常是0（从包头开始）
- 结束是CRC字段之前的最后一个字节的索引
- 使用 `-1` 表示"当前CRC字段之前"

**计算方法**:
```
假设数据包: [A(1字节)] [B(2字节)] [C(1字节)] [CRC8(1字节)]
字节索引:     0          1-2         3          4

CRC8校验前4字节: range: [0, 4]
或使用自动: range: [0, -1]
```

### Q3: 为什么模拟模式CRC校验失败？

**A**: v2.0已修复！旧版本问题：
- 问题: 模拟器先填充所有字段，再计算CRC时位置已被占用
- 解决: 使用两遍生成法 - 第一遍填充数据，第二遍计算CRC

### Q4: 浮点数精度问题？

**A**: 
- `float` (4字节): 约7位有效数字
- `double` (8字节): 约15位有效数字
- 传感器数据通常用float足够
- 科学计算或高精度需求用double

### Q5: 字节序如何选择？

**A**:
- **小端序** (`little`): 大多数嵌入式系统、x86、ARM
- **大端序** (`big`): 网络协议、部分处理器
- **不确定时**: 优先尝试`little`

### Q6: 如何验证配置文件语法？

**A**:
```bash
# YAML验证
python -c "import yaml; print(yaml.safe_load(open('config.yaml')))"

# JSON验证
python -c "import json; print(json.load(open('config.json')))"
```

### Q7: 数据包大小限制？

**A**: 无硬性限制，但建议：
- 单包 < 1KB（实时性考虑）
- 字段数 < 50个（可读性考虑）
- 实际限制取决于串口缓冲区和协议设计

### Q8: 模拟器可以模拟错误包吗？

**A**: 当前版本只生成正确的数据包。如需错误包测试：
- 手动修改下位机代码注入错误
- 或修改工具代码添加错误注入功能
