# 通用数据包验证工具 - 完整使用指南

一个基于配置驱动的通用串口数据包验证工具，支持YAML/JSON配置，适配任何项目的通信协议。

---

## 📦 目录结构

```
packet_validator_tool/
├── universal_packet_validator.py       # 主程序
├── protocol_configs/                   # 协议配置文件目录
│   ├── rm_vision_protocol.yaml        # RM视觉协议(YAML)
│   ├── rm_vision_protocol.json        # RM视觉协议(JSON)
│   ├── example_protocol.yaml          # 示例协议
│   └── simple_sensor_protocol.yaml    # 简单传感器协议
├── 使用指南.md                         # 本文档
├── 配置参考.md                         # 配置文件详细说明
└── 更新日志.md                         # 版本历史和问题修复

## ✨ 主要特性

- ✅ **配置驱动** - 无需修改代码，通过YAML/JSON配置适配新协议
- ✅ **双模式** - 串口模式（真实硬件）+ 模拟模式（无需硬件测试）
- ✅ **多种校验** - CRC8、CRC16、简单校验和、固定值验证
- ✅ **图形界面** - PyQt5界面，实时显示和统计
- ✅ **灵活模拟器** - 支持固定值、计数器、随机数、公式计算
- ✅ **蓝牙过滤** - 自动过滤蓝牙串口，只显示虚拟串口和硬件串口
- ✅ **100%校验** - v2.0修复了模拟模式CRC校验问题

## 🚀 快速开始

### 1. 安装依赖

```bash
pip install PyQt5 pyserial pyyaml
```

### 2. 运行工具

```bash
# 使用YAML配置（推荐）
python universal_packet_validator.py protocol_configs/rm_vision_protocol.yaml

# 使用JSON配置（兼容v1.0）
python universal_packet_validator.py protocol_configs/rm_vision_protocol.json

# 不带参数启动，在GUI中加载配置
python universal_packet_validator.py
```

### 3. 使用界面

1. **选择工作模式**：串口模式或模拟模式
2. **串口模式**：选择COM口和波特率，点击"启动"
3. **模拟模式**：设置发送间隔，点击"启动"
4. **查看结果**：绿色=验证通过，红色=验证失败

## 🎯 界面说明

### 连接设置区域

#### **工作模式**
- **串口模式**: 连接真实硬件设备（如Arduino、STM32）
  - 用途：验证实际下位机发送的数据包
  - 需要：硬件设备 + USB串口线
  
- **模拟模式**: 软件自动生成测试数据包
  - 用途：无硬件时测试协议配置是否正确
  - 优点：快速验证工具功能和配置文件

#### **串口配置**（仅串口模式）
- **串口选择**: 显示可用的COM口
  - 格式：`COM3 - USB Serial Port`
  - 自动过滤蓝牙串口（识别BTHENUM）
  - 点击"刷新"按钮重新扫描
  
- **波特率**: 必须与下位机一致
  - 推荐：`115200`（标准通信速率）
  - 其他：`921600`, `460800`, `230400`, `9600`

#### **模拟器配置**（仅模拟模式）
- **发送间隔(秒)**: 数据包生成间隔（1-10秒）
  - 建议：1秒（方便快速测试）

#### **控制按钮**
- **启动**: 开始接收/生成数据
- **停止**: 停止当前连接
- **清空日志**: 清除所有记录和统计

### 数据解析区域

#### **数据包表格**
显示解析后的数据包详细信息：

| 列名 | 说明 | 示例 |
|------|------|------|
| **字段名** | 协议中定义的字段名称 | "帧头SOF", "CRC8" |
| **值** | 解析后的实际数值 | 165, 3.14 |
| **十六进制** | 原始字节的十六进制表示 | A5, 3F 80 00 00 |
| **描述** | 字段的功能说明 | "起始标志(0xA5)" |

**颜色标识**:
- 🟢 **绿色背景**: 数据包验证通过
- 🔴 **红色背景**: 数据包验证失败

#### **接收日志**
实时显示数据包的接收和验证情况：
- 正常消息：黑色文字
- 错误消息：红色文字
- 格式：`[时:分:秒] 消息内容`

示例：
```
[14:23:15] 已启动模拟器, 发送间隔: 1秒
[14:23:16] 数据包 #1: 验证通过 ✓
[14:23:17] 数据包 #2: 验证通过 ✓
```

### 统计信息区域

| 指标 | 说明 | 颜色含义 |
|------|------|----------|
| **总数据包** | 接收到的数据包总数 | 黑色 |
| **有效** | 通过所有验证的数据包数量 | 绿色 |

## 📝 配置文件快速入门

### 最简配置示例（YAML格式）

```yaml
protocol_name: 我的协议
description: 简单的传感器协议
frame_header: "0xA5"
byte_order: little

fields:
  - name: 帧头
    size: 1
    type: uint8
    description: 起始标志
    validation:
      type: fixed_value
      value: 165  # 0xA5 = 165

  - name: 温度
    size: 2
    type: int16
    description: 温度值(℃ * 10)

  - name: 湿度
    size: 2
    type: uint16
    description: 湿度值(% * 10)

  - name: 校验和
    size: 1
    type: uint8
    description: 简单校验和
    validation:
      type: checksum
      range: [0, 5]

simulator:
  enabled: true
  generate_rules:
    帧头: "fixed:0xA5"
    温度: "random:200-300"
    湿度: "random:400-600"
```

### 支持的数据类型

| 类型 | 字节数 | 取值范围 | 用途 |
|------|--------|----------|------|
| `uint8` | 1 | 0 ~ 255 | 标志位、小整数 |
| `uint16` | 2 | 0 ~ 65535 | ID、命令码 |
| `uint32` | 4 | 0 ~ 4294967295 | 计数器、时间戳 |
| `int8` | 1 | -128 ~ 127 | 小的有符号数 |
| `int16` | 2 | -32768 ~ 32767 | 温度等传感器值 |
| `int32` | 4 | -2^31 ~ 2^31-1 | 大的有符号数 |
| `float` | 4 | ±3.4E±38 | 角度、坐标 |
| `double` | 8 | ±1.7E±308 | 高精度数值 |

### 支持的验证类型

#### 1. **fixed_value** - 固定值验证
用于验证帧头、魔数等固定值
```yaml
validation:
  type: fixed_value
  value: 165  # 期望值（0xA5）
```

#### 2. **crc8** - CRC8校验
用于包头校验
```yaml
validation:
  type: crc8
  range: [0, 4]  # 校验第0-3字节
```
- **range**: `[起始位置, 结束位置]`
- 起始位置通常为0（包头）
- 结束位置为CRC8字段之前的最后一个字节索引

#### 3. **crc16** - CRC16校验
用于整包数据完整性验证
```yaml
validation:
  type: crc16
  range: [0, -1]  # 校验整个数据包
```
- `[0, -1]`: 从包头到CRC16字段之前的所有数据
- `-1` 表示"到CRC16字段之前"

#### 4. **checksum** - 简单校验和
所有字节累加后取低8位
```yaml
validation:
  type: checksum
  range: [0, -1]
```

### 模拟器生成规则

| 规则格式 | 说明 | 示例 |
|----------|------|------|
| `fixed:值` | 固定值 | `fixed:0xA5`, `fixed:100` |
| `counter` | 递增计数器 | 从0开始，每次+1 |
| `random:最小-最大` | 随机数 | `random:1-100`, `random:0.5-10.0` |
| `formula:表达式` | 公式计算 | `formula:counter*0.1` |

**示例**:
```yaml
generate_rules:
  帧头: "fixed:0xA5"              # 始终0xA5
  序列号: "counter"                # 0, 1, 2, 3...
  温度: "random:200-300"          # 20.0°C ~ 30.0°C
  角度: "formula:counter*0.1"     # 0, 0.1, 0.2...
  距离: "random:0.5-10.0"         # 0.5m ~ 10.0m随机
```

**注意**: CRC字段会自动计算，无需在generate_rules中指定

## 🔧 创建自定义协议

### 步骤1: 创建配置文件

复制示例配置作为模板：
```bash
cp protocol_configs/example_protocol.yaml my_protocol.yaml

### 步骤2: 编辑配置

```yaml
protocol_name: "我的自定义协议"
description: "用于XXX设备的通信协议"
frame_header: "0xAA"
byte_order: "little"

fields:
  - name: "帧头"
    size: 1
    type: "uint8"
    description: "起始标志(0xAA)"
    validation:
      type: "fixed_value"
      value: 170

  - name: "数据1"
    size: 2
    type: "uint16"
    description: "第一个数据字段"

  - name: "CRC16"
    size: 2
    type: "uint16"
    description: "整包校验"
    validation:
      type: "crc16"
      range: [0, -1]

simulator:
  enabled: true
  generate_rules:
    "帧头": "fixed:0xAA"
    "数据1": "random:0-1000"
```

### 步骤3: 运行测试

```bash
python universal_packet_validator.py my_protocol.yaml
```

### 步骤4: 验证结果

1. 选择"模拟模式"
2. 点击"启动"
3. 观察统计信息 → 应显示 **100%成功率(绿色)** ✓

## 📖 使用示例

### 示例1: RM视觉协议

```bash
python universal_packet_validator.py protocol_configs/rm_vision_protocol.yaml
```

**协议特点:**
- 帧头: 0xA5
- 双重校验：CRC8包头校验 + CRC16整包校验

创建 `arduino_sensor.yaml`：
```yaml
protocol_name: Arduino温湿度传感器
byte_order: little

fields:
  - name: 帧头
    size: 1
    type: uint8
    validation:
      type: fixed_value
      value: 255  # 0xFF

  - name: 温度
    size: 2
    type: int16
    description: 温度*10

  - name: 湿度
    size: 2
    type: uint16
    description: 湿度*10

  - name: 校验和
    size: 1
    type: uint8
    validation:
      type: checksum
      range: [0, 5]

simulator:
  enabled: true
  generate_rules:
    帧头: "fixed:0xFF"
    温度: "random:200-300"
    湿度: "random:400-600"
```

运行：
```bash
python universal_packet_validator.py arduino_sensor.yaml
```

## 🔍 故障排除

### ❌ 问题1: 模拟模式CRC校验失败

**状态**: ✅ 已在v2.0修复！

如果仍然出现：
1. 确认使用最新版本代码
2. 检查配置文件中CRC的`range`参数是否正确
3. 参考 [更新日志.md](更新日志.md) 了解修复详情

**CRC8 range示例**:
```yaml
- name: "CRC8"
  validation:
    type: "crc8"
    range: [0, 4]  # 校验前4个字节（索引0,1,2,3）
```

### ❌ 问题2: 找不到串口设备

**检查步骤**:
1. 确认设备已插入USB口
2. 查看设备管理器中是否有COM口
3. 安装驱动（CH340、CP2102等）
4. 点击"刷新"按钮重新扫描
5. 检查是否被其他程序占用

**注意**: 工具会自动过滤蓝牙串口（识别BTHENUM）

### ❌ 问题3: 配置文件加载失败

**常见原因**:
- YAML缩进错误（必须用空格，不能用Tab）
- 冒号后面缺少空格
- 字符串未加引号（包含特殊字符时）
- JSON格式错误（缺少逗号、引号等）

**验证工具**:
```bash
# 测试YAML语法
python -c "import yaml; print(yaml.safe_load(open('your.yaml')))"

# 测试JSON语法
python -c "import json; print(json.load(open('your.json')))"
```

### ❌ 问题4: 数据包长度不匹配

**解决方案**:
1. 计算配置文件中所有字段的size之和
2. 确认与实际协议文档一致
3. 检查是否遗漏或多定义了字段

示例：
```yaml
fields:
  - name: 帧头      # size: 1
  - name: 长度      # size: 2
  - name: 数据      # size: 10
  - name: CRC16    # size: 2
# 总计: 1 + 2 + 10 + 2 = 15字节
```

### ❌ 问题5: 浮点数显示不正确

**检查**:
1. 确认`byte_order`设置正确（通常为`little`）
2. 确认下位机发送的是IEEE 754标准浮点格式
3. 检查字段size是否为4字节（float）或8字节（double）

### ❌ 问题6: 成功率低（串口模式）

**排查步骤**:
1. 检查波特率是否与下位机一致
2. 检查字节序（byte_order）配置
3. 确认CRC算法与下位机一致
4. 使用模拟模式验证工具本身是否正常
5. 检查串口线质量和连接稳定性

### ❌ 问题7: ModuleNotFoundError

```bash
# 缺少yaml模块
pip install pyyaml

# 缺少serial模块
pip install pyserial

# 缺少PyQt5模块
pip install PyQt5
```

## 💡 高级技巧

### 1. 动态数据长度字段
```yaml
- name: "数据长度"
  size: 2
  type: "uint16"
  description: "数据段长度"
  # 模拟器会自动计算正确的长度
```

### 2. 多字节固定值（魔数）
```yaml
- name: "魔数"
  size: 4
  type: "uint32"
  description: "协议标识"
  validation:
    type: "fixed_value"
    value: 0x12345678  # 十六进制或十进制都可以
```

### 3. 公式生成正弦波数据
```yaml
generate_rules:
  "信号": "formula:50*sin(counter*0.1)+50"
```
注意：需要在代码中导入math库

### 4. 调试生成的数据包
在 `SimulatorThread.generate_packet()` 末尾添加：
```python
print(f"生成数据包: {packet.hex()}")
return bytes(packet)
```

### 5. 查看CRC计算过程
在CRC计算部分添加调试输出：
```python
crc_data = packet[start:end]
crc_value = CRC8Table.calculate(crc_data)
print(f"CRC8: 数据={crc_data.hex()}, 计算值={crc_value:02X}")
```
