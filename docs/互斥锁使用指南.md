# 互斥锁（Mutex）使用指南

## 1. 什么是互斥锁？

**互斥锁（Mutex = Mutual Exclusion）** 是一种同步机制，用于保护共享资源，防止多个线程同时访问造成数据竞争。

### 核心原理
```
线程A尝试访问共享数据
    ↓
获取锁（lock）
    ↓
访问/修改共享数据（临界区）
    ↓
释放锁（unlock）
    ↓
其他线程现在可以获取锁
```

只有持有锁的线程能访问被保护的资源，其他线程必须等待。

---

## 2. 为什么需要互斥锁？

### 问题场景：数据竞争

```cpp
// 没有锁保护
class Counter {
    int count = 0;
    
    void increment() {
        count++;  // 看起来简单，实际包含3步：
                  // 1. 读取 count
                  // 2. 加1
                  // 3. 写回 count
    }
};

// 两个线程同时调用 increment()
线程A: 读取 count = 0
线程B: 读取 count = 0  ← 还没看到A的修改
线程A: 计算 0+1=1
线程B: 计算 0+1=1
线程A: 写回 count = 1
线程B: 写回 count = 1  ← 覆盖了A的结果
// 结果：调用了2次，但 count = 1（期望是2）
```

### 使用锁后

```cpp
class Counter {
    int count = 0;
    std::mutex mtx;
    
    void increment() {
        std::lock_guard<std::mutex> lock(mtx);
        count++;  // 只有一个线程能执行
    }
};

// 两个线程同时调用
线程A: 获取锁 → count++ → 释放锁
线程B: 等待 → 获取锁 → count++ → 释放锁
// 结果：count = 2 ✓
```

## 3. 互斥锁的典型使用场景

### 场景1: 保护共享数据的读写

**自瞄代码示例** - [commandgener.cpp](sp_vision_25-main/tasks/auto_aim/multithread/commandgener.cpp):

```cpp
class CommandGener {
private:
    std::optional<Input> latest_;  // 共享数据
    std::mutex mtx_;               // 保护锁
    
    // 主线程写入
    void push(const std::list<Target> & targets, 
              const std::chrono::steady_clock::time_point & t,
              double bullet_speed, 
              const Eigen::Vector3d & gimbal_pos) 
    {
        std::lock_guard<std::mutex> lock(mtx_);  // 加锁
        latest_ = {targets, t, bullet_speed, gimbal_pos};
        cv_.notify_one();  // 唤醒命令生成线程
    }  // 自动解锁
    
    // 命令生成线程读取
    void generate_command() {
        while (!stop_) {
            std::optional<Input> input;
            {
                std::lock_guard<std::mutex> lock(mtx_);  // 加锁
                if (latest_ && delta_time(...) < 0.2) {
                    input = latest_;  // 安全读取
                }
            }  // 解锁
            
            if (input) {
                // 处理数据（已经释放锁，不阻塞其他线程）
                auto command = aimer_.aim(input->targets_, ...);
                cboard_.send(command);
            }
        }
    }
};
```

**为什么需要锁**？
- 主线程正在写入 `latest_` 的一半时
- 命令生成线程开始读取
- 没有锁：读到不完整的数据 → 崩溃
- 有锁：命令生成线程等待主线程写完

### 场景2: 保护硬件设备访问

**自瞄代码示例** - [usbcamera.cpp:73-82](sp_vision_25-main/io/usbcamera/usbcamera.cpp#L73-L82):

```cpp
class USBCamera {
private:
    cv::VideoCapture cap_;  // 相机设备对象
    std::mutex cap_mutex_;  // 保护相机访问
    std::thread daemon_thread_;   // 守护线程
    std::thread capture_thread_;  // 采集线程
    
    // 采集线程读取图像
    cv::Mat read() {
        std::lock_guard<std::mutex> lock(cap_mutex_);
        if (!cap_.isOpened()) {
            return cv::Mat();
        }
        cap_ >> img_;  // 从相机读取
        return img_;
    }
    
    // 守护线程关闭相机
    void close() {
        std::lock_guard<std::mutex> lock(cap_mutex_);
        if (cap_.isOpened()) {
            cap_.release();  // 关闭相机
        }
    }
};
```

**为什么需要锁**？
- 守护线程可能在调用 `close()` 关闭相机
- 采集线程同时在调用 `read()` 读取图像
- 没有锁：在关闭时读取 → 程序崩溃
- 有锁：采集线程等待关闭完成，或守护线程等待读取完成

### 场景3: 保护线程退出标志

**自瞄代码示例** - [perceptron.cpp:34-49](sp_vision_25-main/tasks/omniperception/perceptron.cpp#L34-L49):

```cpp
class Perceptron {
private:
    bool stop_flag_;
    std::mutex mutex_;
    std::condition_variable condition_;
    std::vector<std::thread> threads_;  // 4个推理线程
    
    ~Perceptron() {
        {
            std::unique_lock<std::mutex> lock(mutex_);
            stop_flag_ = true;  // 设置退出标志
        }
        condition_.notify_all();  // 唤醒所有线程
        
        for (auto & t : threads_) {
            if (t.joinable()) {
                t.join();  // 等待线程退出
            }
        }
    }
    
    void parallel_infer(io::USBCamera * cam, 
                        std::shared_ptr<auto_aim::YOLO> & yolov8_parallel) 
    {
        while (true) {
            {
                std::unique_lock<std::mutex> lock(mutex_);
                if (stop_flag_) break;  // 检查退出标志
            }
            
            // 继续工作...
            cam->read(usb_img, ts);
            auto armors = yolov8_parallel->detect(usb_img);
        }
    }
};
```

**为什么需要锁**？
- 析构函数（主线程）设置 `stop_flag_ = true`
- 4个推理线程同时检查 `if (stop_flag_)`
- 没有锁：可能读到不一致的值
- 有锁：确保所有线程都能看到最新的退出标志

### 场景4: 保护容器操作

```cpp
class DataProcessor {
private:
    std::vector<cv::Mat> image_buffer_;
    std::mutex buffer_mutex_;
    
    void add_image(const cv::Mat & img) {
        std::lock_guard<std::mutex> lock(buffer_mutex_);
        image_buffer_.push_back(img);  // 修改容器
    }
    
    cv::Mat get_image() {
        std::lock_guard<std::mutex> lock(buffer_mutex_);
        if (image_buffer_.empty()) return cv::Mat();
        cv::Mat img = image_buffer_.back();
        image_buffer_.pop_back();  // 修改容器
        return img;
    }
};
```

**为什么需要锁**？
- `std::vector` 不是线程安全的
- 多个线程同时 `push_back` 或 `pop_back` 会导致内存损坏

## 4. 不需要互斥锁的场景

### 场景1: 使用原子操作

**自瞄代码示例** - [mt_standard.cpp:61-62](sp_vision_25-main/src/mt_standard.cpp#L61-L62):

```cpp
std::atomic<io::Mode> mode{io::Mode::idle};
auto last_mode{io::Mode::idle};

// 主线程写入（不需要锁）
mode = cboard.mode;

// 检测线程读取（不需要锁）
if (mode.load() == io::Mode::auto_aim) {
    camera.read(img, t);
}
```

**为什么不需要锁**？
- `std::atomic` 保证操作的原子性
- 读写不会被中断
- 比互斥锁性能更好

### 场景2: 使用线程安全的数据结构

**自瞄代码示例** - [dm_imu.cpp:86](sp_vision_25-main/io/dm_imu/dm_imu.cpp#L86):

```cpp
tools::ThreadSafeQueue<IMUData> queue_;  // 内部已有锁

// IMU接收线程（不需要额外的锁）
queue_.push({q, timestamp});

// 主线程（不需要额外的锁）
queue_.pop(data_ahead_);
```

**为什么不需要锁**？
- `ThreadSafeQueue` 内部已经使用互斥锁保护
- 不需要重复加锁

### 场景3: 线程独立的局部变量

```cpp
void parallel_infer() {
    cv::Mat img;  // 每个线程独立的栈变量
    std::chrono::steady_clock::time_point ts;
    
    cam->read(img, ts);  // 不需要锁
    auto armors = yolo->detect(img);  // 不需要锁
}
```

**为什么不需要锁**？
- 每个线程有自己独立的栈空间
- 局部变量不被其他线程访问

### 场景4: 只读的共享数据

```cpp
const std::string config_path = "config.yaml";

// 多个线程读取（不需要锁）
void thread1() { auto yaml = load(config_path); }
void thread2() { auto yaml = load(config_path); }
```

**为什么不需要锁**？
- 数据是常量，不会被修改
- 多个线程同时读取是安全的

## 5. 互斥锁的使用方式

### 方式1: `std::lock_guard`（推荐）

```cpp
void update_data() {
    std::lock_guard<std::mutex> lock(mtx_);
    // 临界区代码
    data_ = new_data;
}  // 离开作用域自动解锁，异常安全
```

**优点**：
- RAII机制，自动管理锁的生命周期
- 异常安全（即使抛出异常也会解锁）
- 代码简洁

### 方式2: `std::unique_lock`（需要灵活控制）

```cpp
void complex_operation() {
    std::unique_lock<std::mutex> lock(mtx_);
    
    // 临界区1
    prepare_data();
    
    lock.unlock();  // 手动解锁
    
    // 耗时操作（不持有锁）
    process_heavy_computation();
    
    lock.lock();  // 重新加锁
    
    // 临界区2
    save_result();
}
```

**适用场景**：
- 需要在临界区中间释放锁
- 需要延迟加锁
- 配合条件变量使用

### 方式3: 配合条件变量（生产者-消费者模式）

```cpp
std::mutex mtx_;
std::condition_variable cv_;
std::queue<Task> tasks_;

// 生产者
void push_task(const Task & task) {
    {
        std::lock_guard<std::mutex> lock(mtx_);
        tasks_.push(task);
    }
    cv_.notify_one();  // 唤醒一个等待的消费者
}

// 消费者
void process_tasks() {
    while (true) {
        std::unique_lock<std::mutex> lock(mtx_);
        cv_.wait(lock, [this] { return !tasks_.empty(); });
        // wait会自动释放锁并等待，被唤醒后重新获取锁
        
        Task task = tasks_.front();
        tasks_.pop();
        lock.unlock();  // 处理任务前释放锁
        
        process(task);
    }
}
```

## 6. 常见错误与解决方案

### 错误1: 死锁

```cpp
std::mutex mutex1, mutex2;

// 线程A
void thread_a() {
    std::lock_guard<std::mutex> lock1(mutex1);
    // 一些操作...
    std::lock_guard<std::mutex> lock2(mutex2);  // 等待 mutex2
}

// 线程B
void thread_b() {
    std::lock_guard<std::mutex> lock2(mutex2);
    // 一些操作...
    std::lock_guard<std::mutex> lock1(mutex1);  // 等待 mutex1
}
// 结果：两个线程互相等待 → 死锁！
```

**解决方案1：固定加锁顺序**
```cpp
// 总是先锁 mutex1，再锁 mutex2
void thread_a() {
    std::lock_guard<std::mutex> lock1(mutex1);
    std::lock_guard<std::mutex> lock2(mutex2);
}

void thread_b() {
    std::lock_guard<std::mutex> lock1(mutex1);  // 相同顺序
    std::lock_guard<std::mutex> lock2(mutex2);
}
```

**解决方案2：使用 `std::lock` 同时获取多个锁**
```cpp
void safe_operation() {
    std::unique_lock<std::mutex> lock1(mutex1, std::defer_lock);
    std::unique_lock<std::mutex> lock2(mutex2, std::defer_lock);
    std::lock(lock1, lock2);  // 同时获取，避免死锁
}
```

### 错误2: 忘记解锁

```cpp
void unsafe_operation() {
    mtx_.lock();
    
    if (error_condition) {
        return;  // ❌ 忘记解锁！
    }
    
    process_data();
    mtx_.unlock();
}
```

**解决方案：始终使用 RAII**
```cpp
void safe_operation() {
    std::lock_guard<std::mutex> lock(mtx_);
    
    if (error_condition) {
        return;  // ✓ 自动解锁
    }
    
    process_data();
}  // ✓ 自动解锁
```

### 错误3: 锁的粒度太大

```cpp
void inefficient() {
    std::lock_guard<std::mutex> lock(mtx_);
    
    // 长时间持有锁
    camera.read(img);          // 耗时
    process_image(img);        // 耗时
    detector.detect(img);      // 耗时  ← 其他线程一直等待
    save_result(result);
}
```

**解决方案：缩小锁的范围**
```cpp
void efficient() {
    cv::Mat img;
    {
        std::lock_guard<std::mutex> lock(mtx_);
        camera.read(img);  // 只在必要时持有锁
    }
    
    process_image(img);    // 释放锁后处理
    auto result = detector.detect(img);
    
    {
        std::lock_guard<std::mutex> lock(mtx_);
        save_result(result);  // 必要时重新加锁
    }
}
```

### 错误4: 在持有锁时调用外部代码

```cpp
class DataManager {
    std::mutex mtx_;
    std::vector<Observer*> observers_;
    
    void notify_observers(const Data & data) {
        std::lock_guard<std::mutex> lock(mtx_);
        for (auto obs : observers_) {
            obs->on_data(data);  // ❌ 外部回调可能导致死锁
        }
    }
};
```

**解决方案：先复制，再调用**
```cpp
void notify_observers(const Data & data) {
    std::vector<Observer*> obs_copy;
    {
        std::lock_guard<std::mutex> lock(mtx_);
        obs_copy = observers_;  // 复制一份
    }
    
    // 释放锁后调用外部代码
    for (auto obs : obs_copy) {
        obs->on_data(data);
    }
}
```

## 7. 性能优化建议

### 建议1: 减少锁的持有时间

```cpp
// ❌ 不好
void slow() {
    std::lock_guard<std::mutex> lock(mtx_);
    auto data = fetch_data();      // 耗时
    auto result = process(data);   // 耗时
    save_result(result);
}

// ✓ 更好
void fast() {
    Data data;
    {
        std::lock_guard<std::mutex> lock(mtx_);
        data = fetch_data();
    }
    
    auto result = process(data);  // 不持有锁
    
    {
        std::lock_guard<std::mutex> lock(mtx_);
        save_result(result);
    }
}
```

### 建议2: 使用读写锁（多读少写场景）

```cpp
#include <shared_mutex>

class Cache {
private:
    std::shared_mutex mtx_;
    std::map<int, Data> cache_;
    
    // 多个线程可以同时读
    Data read(int key) {
        std::shared_lock<std::shared_mutex> lock(mtx_);
        return cache_[key];
    }
    
    // 只有一个线程可以写
    void write(int key, const Data & data) {
        std::unique_lock<std::shared_mutex> lock(mtx_);
        cache_[key] = data;
    }
};
```

### 建议3: 避免锁竞争

```cpp
// ❌ 单个锁，高竞争
class GlobalCounter {
    std::mutex mtx_;
    int count_ = 0;
    
    void increment() {
        std::lock_guard<std::mutex> lock(mtx_);
        count_++;
    }
};

// ✓ 每个线程独立计数，最后合并
class ThreadLocalCounter {
    thread_local static int local_count_;
    
    void increment() {
        local_count_++;  // 无锁
    }
    
    int total() {
        // 只在最后汇总时加锁
        // ...
    }
};
```

## 9. 总结

### 何时使用互斥锁？

✅ **需要锁**：
- 多个线程读写同一个变量
- 多个线程访问同一个硬件设备（相机、串口）
- 多个线程修改同一个容器（vector、map等）
- 需要保护的临界区

❌ **不需要锁**：
- 线程独立的局部变量
- 已经使用原子操作（`std::atomic`）
- 已经使用线程安全的数据结构（如 `ThreadSafeQueue`）
- 只读的共享常量

### 核心原则

> **只要有共享资源被多个线程访问，且至少有一个线程会修改它，就需要互斥锁保护。**

### 最佳实践

1. **使用 RAII**：优先使用 `std::lock_guard`，避免忘记解锁
2. **缩小锁的范围**：只在必要时持有锁，减少锁竞争
3. **固定加锁顺序**：避免死锁
4. **避免嵌套锁**：如果必须使用多个锁，用 `std::lock` 同时获取
5. **在持有锁时不要调用外部代码**：可能导致死锁或性能问题
