## 4. 线程生命周期

```
程序启动
   │
   ├──→ 创建相机对象 (启动相机内部的守护+采集线程)
   │
   ├──→ 创建CBoard对象 (启动IMU接收线程)
   │
   ├──→ 创建CommandGener对象 (启动命令生成线程)
   │
   ├──→ 创建检测线程 detect_thread
   │         │
   │         └──→ 循环: 如果模式=auto_aim → 读取相机 → 推送到队列
   │
   └──→ 主线程进入主循环
            │
            ├──→ 读取模式 (从CBoard)
            │
            ├──→ 如果模式=auto_aim:
            │    │
            │    ├──→ 从检测队列pop装甲板
            │    ├──→ 从IMU队列获取姿态
            │    ├──→ 目标追踪
            │    └──→ 推送给命令生成线程
            │
            ├──→ 如果模式=small_buff/big_buff:
            │    │
            │    ├──→ 读取相机
            │    ├──→ 检测能量机关
            │    ├──→ 解算目标
            │    └──→ 直接发送指令
            │
            └──→ exiter.exit() → 退出循环

程序退出
   │
   ├──→ detect_thread.join() (等待检测线程退出)
   │
   ├──→ CommandGener析构 (停止命令生成线程)
   │
   ├──→ CBoard析构 (停止IMU线程)
   │
   └──→ Camera析构 (停止相机线程)
```

## 6. 性能特点

### 并行度
- **4-5个线程同时运行**：检测、主流程、命令生成、IMU接收、相机采集
- **流水线并行**：图像采集不阻塞检测，检测不阻塞追踪，追踪不阻塞指令生成

### 关键路径延迟
```
相机读取 → 神经网络推理 → 目标追踪 → 瞄准解算 → 串口发送
  │           │              │          │           │
  5ms        10ms           2ms        3ms         1ms
  └────────────────── 总延迟约 20-30ms ──────────────┘
```

### 队列深度
- **MultiThreadDetector队列**: 16帧 (防止丢帧)
- **IMU队列**: 5000条 (高频数据缓冲)
- **命令生成**: 无队列，只保留最新数据

## 7. 线程同步点

```
时刻T0: 相机曝光开始
时刻T1: 相机读取完成 → 检测线程push()
时刻T2: 主线程pop() → 获取检测结果
时刻T3: 主线程imu_at(T1) → 获取T1时刻的IMU姿态(插值)
时刻T4: 主线程tracker.track() → 目标追踪
时刻T5: 主线程push() → 推送给命令生成线程
时刻T6: 命令生成线程生成指令 → 串口发送

关键: T3的IMU数据必须对应T1时刻，通过时间戳插值实现时间同步
```

## 8. 与 sentry_multithread 的对比

| 特性 | mt_standard | sentry_multithread |
|------|-------------|-------------------|
| 检测线程 | 1个专用线程 | 无(主线程串行) |
| 命令生成 | 异步线程 | 主线程同步 |
| 全向感知 | 无 | 4个并行推理线程 |
| USB相机 | 无 | 4个相机×2线程 |
| 总线程数 | 6-7个 | 16+个 |
| 适用场景 | 标准步兵/英雄 | 哨兵(360度感知) |

## 总结

**mt_standard 的线程设计核心思想**：
1. **生产者-消费者模式**：检测线程生产，主线程消费
2. **异步命令生成**：不阻塞主流程的目标追踪
3. **时间同步**：通过时间戳插值实现多传感器融合
4. **容错设计**：守护线程自动恢复断线设备
